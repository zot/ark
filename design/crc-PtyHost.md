# PtyHost
**Requirements:** R3114, R3115, R3116, R3117, R3118, R3119, R3120, R3121, R3122, R3124, R3125, R3126, R3127, R3128, R3136, R3139, R3323, R3324, R3326, R3327, R3329, R3330, R3333, R3334, R3335, R3336, R3337, R3338, R3339, R3340, R3341, R3342, R3343

The server-side owner of one hosted Claude Code pty session. Holds the pty
master and the `claude` child, multiplexes the child's byte stream out to a set
of attached clients, and owns the launch/stop/status lifecycle. A Closure Actor
(ChanSvc): access to the master, the child, and the client set is serialized
through its channel, so no lock is held across pty I/O.

## Knows
- master: the pty master (creack/pty) for the hosted session; nil when none is hosted (R3116).
- child: the `claude` child process; dies on `ark stop`, never auto-relaunched (R3114, R3116).
- clients: the set of attached clients, each addressed through the transport-agnostic client interface (R3117); zero clients is a valid running state (R3121), and the ordinary one for a detached session.
- (per connection) pending / spare / writing: the double buffer and the in-flight flag that drive one connection's output (R3336). `pending` is what the actor appends into; `spare` is the idle buffer, nil while a write goroutine holds it; `writing` says a writer is in flight. All three are actor-owned, which is why `writing` needs no atomic — its only false→true transition happens inside the actor (R3338). There is **no client-count mirror**: R3328's existed to let the reader skip a *synchronous* round-trip, and the hand-off is a post now (R3335), so the actor is again the only place the client set is known.
- readBuf: the single read buffer, one allocation for the life of the session (R3333). Never a field the actor reads — it travels: read goroutine → actor closure → successor goroutine, owned by exactly one of them at any instant.
- sessionID: the hosted session's Claude Code id, learned from the seat claim at launch (R3126).
- bootstrap: the first-input string sent at launch (default `load /luhmann`, R3122).
- (no model state) — the child's argv is **asked for, not composed here**: launch takes an optional model parameter and hands it to the env, which resolves parameter → `[luhmann] model` → compiled-in default and returns the whole argv (R3329, R3330). The host stays ignorant of config, so it remains testable with a fake env, and there is one place the resolution rule can be wrong. A resolution error — an explicit model against a `command` override (R3331) — fails the launch **before the fork**, so no child is started and nothing needs unwinding.
- (no trust state) — the "trust this folder" accepter is **per-launch**, owned by that launch's read chain, not a field here (R3327).

## Does
- launch: reject if a session is already hosted; clear any stale seat claim (ForceReleaseSeat, R3126); fork the pty (cwd `~/.ark/luhmann`), start the **child command** with a clean child environment (childEnv, R3127), then run the content-free confirmation protocol (R3126) — send the bootstrap, await the seat claim (the sole authoritative confirmation) — and return success or a timeout error. The sole spend-consent gate (R3114, R3122). **Publishes its outcome before returning** — `@luhmann-hosted: <session>` on confirmation, `@luhmann-launch-failed: <reason>` on abandonment, both by replacing `tmp://luhmann/launch.md` so only changed pairs fire (R3326). Publishing *here* rather than at a caller is what makes every way in announce identically: a CLI `ark luhmann launch` over the API and the `sys.luhmannLaunch()` binding (R3325) pass through this one point, so a UI showing the terminal wakes on a launch it did not start. Same chokepoint reasoning as finalize's, in the other direction.
- childEnv: build the child's environment from the server's, stripping the Claude Code session-identity markers (`CLAUDECODE`, `CLAUDE_CODE_*`, `AI_AGENT`) so the hosted `claude` comes up as a fresh top-level session, not a detected sub-session that refuses to complete a turn; credentials (`ANTHROPIC*`) and other config pass through, and `TERM` is ensured (R3127). It also *sets* `ARK_MANAGED_PTY=1` so the hosted session can tell it was started by the managed launch (vs. a bare `/luhmann` elsewhere) and surface the detach hint (R3139).
- trustAccepter (per-launch object, R3327): for a launch into a directory Claude Code has not seen, watch the child's early output and, on the "trust this folder" dialog, select the "Yes, I trust" option by the number read from the escape-stripped stream — before the bootstrap, so the menu does not consume it. Reads the number rather than assuming a default. Armed only for new projects, disarmed once handled or a timeout elapses, so it cannot misfire on a running session (R3128). **Owned by one launch's read chain, so its scan buffer needs no guard** — held on the host it was shared, because a teardown leaves the old chain draining through the grace window while the reservation check already permits a new launch, and the departing reader could then answer the arriving launch's dialog from the dying session's output (R3327). The chain is a succession of one-shot goroutines rather than a single readLoop (R3333), and exactly one of them exists at a time — the actor spawns the successor — so the accepter is fed by one goroutine at any instant, with the hand-off edges supplying the ordering.
- startRead: spawn the goroutine that owns the read buffer and blocks on the master, then hands the buffer to the actor and terminates (R3333). The read is never taken on the actor: it blocks indefinitely while the child is quiet, and an idle orchestrator goes minutes without a byte, so a read inside a closure would stall every attach, detach, resize, status and stop (R3334). The hand-off is a **post, not a call** — the reader never waits for the distribution to finish (R3335).
- onRead (actor): the other half of the read cycle. Append the bytes to every attached connection, then spawn the successor read goroutine handing back the same buffer — only after the actor is finished with it, which is what makes the ownership exclusive without a guard (R3333). ark never reads the child's output for session *state*; that comes from the JSONL (R3115). A chain whose master is no longer the hosted one keeps reading and **discards**: the output must still be drained or the child blocks (R3121), and it must not reach a later launch's clients (R3343).
- appendOutput (actor): copy one chunk into a connection's pending buffer; drop the connection when that would exceed the byte cap, which is where R3118's bounded-buffer contract is now enforced (R3340). If a write is already in flight, stop — the writer will pick the bytes up; otherwise swap the buffers, set `writing`, and spawn the write goroutine owning the filled one (R3336). Steady state allocates nothing: the two buffers reach their high-water mark and are reused for the life of the connection.
- writeOut (write goroutine): a **blocking, complete** write to the transport, off the actor, then empty the buffer and post the continuation back carrying it (R3336, R3341). Blocking here is correct rather than tolerated — a stalled client blocks only its own writer, its pending grows, and it is dropped at the cap (R3340) while every other connection and the child carry on. A failed write posts a continuation that deregisters instead of one that continues.
- onWritten (actor): the continuation. Take the emptied buffer back as `spare`, clear `writing`, and spawn again if output accumulated meanwhile (R3336) — which is why no wakeup can be lost whichever order the append and the continuation run in (R3337). A continuation whose connection is already gone spawns nothing and returns, or every teardown racing an in-flight write leaks a goroutine (R3342). Order is preserved throughout: appends in read order, buffers out in swap order, one writer at a time (R3339).
- mergeInput: write each client's input to the child, serialized so two clients' bytes cannot interleave mid-sequence (R3119).
- resize: recompute the pty size as the minimum of all attached clients' sizes on every attach, detach, or resize, and `SIGWINCH` the child; a disconnect re-runs the min, so the pty grows when the smallest client leaves (R3120).
- forceRepaint: force the child to repaint the whole screen by toggling the pty size one row (shrink, **hold `ptyRepaintNudge`**, then restore) — a real `SIGWINCH` the Ink TUI redraws on, since a same-size `TIOCSWINSZ` is a kernel no-op. The hold matters: a synchronous shrink-then-restore coalesces and the child sees no net change, so the shrink must persist to be observed. Requested over a `repaint` client→host frame (a third frame kind beside input and resize), so one mechanism serves every transport; used on attach (a new client sees the full screen, not only later output) and on a detach-cancel to wipe the prompt. Needed because ark holds no virtual screen (R3115) — only the child can redraw (R3136).
- attach / detach: register / deregister a client; the session survives zero clients (R3121).
- finalize / finalizeLocked: the single teardown chokepoint, idempotent on master identity, reached both from `stop` and from the read cycle's EOF when the child exits on its own. It comes in two halves because its second caller is now **already on the actor**: `finalizeLocked` is the in-actor body and returns the session it finalized (empty when another caller got there first), and `finalize` is the off-actor wrapper that enters the actor and then discharges the recording. `onRead` calls the locked form directly — calling the wrapper from inside a closure would post to the actor it is already running on and self-deadlock. The file already carries this convention (`recomputeSizeLocked`, `minSizeLocked`). It discharges **both** teardown obligations, so neither path can skip one (R3323): release the Luhmann seat lease, then record an exit for every pool secretary the session was running, so the monitoring log shows no ghosts. The recording runs **off** the actor (the appends are DB writes) and **after** the release, which additionally makes a requeue-driven `pumpCuration` a no-op instead of standing a fresh secretary up into a session being torn down. The caller's reason is carried into the records (R3324). Then clear the actor state, close the clients, and hand the child + master to an off-actor graceful shutdown (R3114, R3116, R3125).
- stop: the graceful-teardown entry point, not a bare kill — ask the child to exit and let it flush its transcript before the kill, and name the reason as ark's own. The obligations themselves belong to finalize (R3125, R3323, R3324).
- status: report whether a session is hosted (master non-nil) plus the pool-secretary roster count from the supervisor state (R3124).

## Collaborators
- attached clients: the transport-agnostic client interface it writes output to and merges input from — PtyAttach (CLI, unix socket) and PtyBrowser (browser, websocket) are its two implementations (R3117, R3144). The interface is a **blocking, complete write plus a close**, and a transport buffers nothing of its own (R3341): the bounded buffering and the drop live in the host, written once instead of once per transport where they could drift. Connected-to.
- Luhmann seat lease: launch waits for the session's `ark luhmann next --first` claim on it — the authoritative confirmation and the session-id source (R3126); the teardown releases the same lease, on either path down (R3125, R3323). Connected-to, not part-of.
- creack/pty: the pty master primitive.
- Config (through the env): the source of the child's argv — the host passes launch's optional model and receives the resolved command (R3329, R3330, R3331). A collaborator reference rather than a config import, so the host never grows a dependency on ark.toml and a fake env still drives it in tests.
- Server: holds the PtyHost and exposes launch/attach/status/stop over the unix socket (R3116).
